# pairing-artifacts — a six-sub-game bundle in the counted format, with games you can replay

Fourteen artifacts for one synthetic counted series (`team-aleph` vs `team-bet`), generated by
[`../gen_pairing_artifacts.py`](../gen_pairing_artifacts.py) — regenerate any time; nothing is
hand-typed and the aggregate is derived from the rows, not restated. The shapes mirror the
[`PAIRING-PLAYBOOK`](../../docs/PAIRING-PLAYBOOK.md) campaign's counted series; the values are
synthetic.

Two gates, both of which it passes:

```bash
python tools/check_artifacts.py examples/pairing-artifacts   # names, ids, keys, arithmetic
python examples/verify_pairing_physics.py                    # the games are actually playable
```

The second exists because the first cannot see inside a sealed payload. An earlier revision of
this bundle shipped one-step logs declaring `capture` (cop three cells away) and `survival`
(threshold 35) — rows asserting `log_verified: true` over games that could not produce their own
results — and `check_artifacts` passed it. That is now a regression gate: every record re-hashes,
every move is legal and on the board, and each sub-game reaches the outcome its row declares.

## Read this before you copy anything

- **The nonces are derivable on purpose.** `nonce()` hashes a guessable tag so the bundle
  regenerates byte-identically. That is what a fixture needs and the opposite of what a game
  needs: with a predictable nonce an opponent recovers your sealed move from its commit *before*
  you reveal it, and the commitment hides nothing. Real nonces come from `secrets.token_hex(16)`.
- **The result file here is pretty-printed; the email must not be.** The emailed report is the
  compact canonical bytes (SPEC §2) — never a re-serialization (SPEC §6).
- **The league fields are ARMED because this is the counted shape.** A warm-up that copies them
  armed is a false declaration under App. E rules 37–38 — see PAIRING-PLAYBOOK stage 4d, and the
  sparring peer's own `runs/` output for the disarmed posture.
- **`league.counted: true` and `_synthetic`** mark what this is. Keep a `league` block in your own
  artifacts; it is the machine-readable counted/uncounted marker rule 52 hangs on.

## What to look at, per file

| File | Worth noticing |
|---|---|
| `declaration_*.json` | The single home for **both teams'** hardware specs and identity; per-group `signature` is sign-then-insert over the block; bare 40-hex `github_commit`. No end time — a pre-game declaration cannot know one |
| `config_*_gNN.json` | The flat **14-key** terms inline — what lets `check_artifacts.py` re-derive the `game_uid` instead of merely checking consistency (WARNINGS §2). `config_sha256` is the canonical hash of those terms (the key was `terms_sha256` before the P5-14 convergence); the pre-game **agreement signature** is a different construction (it binds a nonce, SPEC §4) and rides the wire, not this artifact |
| `log_*_gNN.json` | **Both step-0 spellings in one file** (ours slim + `declaration_ref`, theirs the reference's inline `system_spec`); every step of both sides sealed, so the reveal-and-re-hash audit is demonstrated on a whole game; `role` and `sub_game` inside the signed payload (SPEC §3 replay resistance); a Hebrew hint with an emoji — if your serializer escapes non-ASCII, re-hashing this is how you find out; one deliberate bluff (`intent: "lie"`) in each thief window; `g05` spends a step **placing a barrier instead of moving** (`verdict: "placed_barrier"`), so its capture lands a step later |
| `result_*.json` | The emailed binding report's shape: both teams' repo links under `links.github` (rule 49), per-sub-game `github_commit` maps alternating with the roles, audit verdicts, armed league fields, and `mutual_agreement.sha256` over the SPEC §6 scope |

## The consensus scope

`mutual_agreement.sha256` is hashed over `{game_id, aggregate, sub_games-trimmed-rows}` — the row
keeping `sub_game_number, roles, result, winner_group, score`. That scope is **SPEC §6's
default**, spelled out there key-for-key, not something a pairing has to invent; the serialization
is the pinned spaced form from `vectors/report_consensus.json`. A second team can reproduce this
hash from the result file alone, without reading the generator — which is the property that makes
it worth carrying.

The trimmed row is **not** the document row: the result file's rows carry `tie` (and timestamps,
commits, tokens), the hash rows do not. An earlier revision of this bundle signed `tie` too — a
six-key row matching nothing ever played, including the reference's own sample artifact, live from
2026-08-04 to 2026-08-13 (found by anrbj666 against the reference's bytes; SPEC §6 carries the
full correction). `tools/probes/probe_s6_consensus_scope.py` now recomputes this bundle's shipped
hash from the five-key scope on every CI run, so the scope cannot drift from the reference form
again — a calibrating team that had reproduced the six-key hash should re-run its pre-bind check
against the regenerated bundle.

## What this bundle still does not show

Named honestly, so nobody mistakes coverage for completeness: no technical-loss row, no series
tie, no `disputed_capture`, no equivocation or reorder handling, and no second **team's** copy —
so the cross-team join (`check_artifacts.py <yours> <theirs>`, the check neither team can run
alone) has nothing to join here. For those, run the sparring peer: `python -m sparring.cli
selfplay` writes a real series to `runs/`, including a tie, and its two per-side directories
exercise the join.
